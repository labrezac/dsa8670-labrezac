# Week 5 Reflection

From this week's readings, I learned how version control tracks changes and preserves earlier versions of a project. Commits record individual updates, while branches let me work on changes before merging them into the main branch. This helps keep analytics work organized and makes mistakes easier to correct.

One challenge was understanding how to link an Issue to a pull request. I sought guidance and learned to include `Closes #<issue-number>` in the pull request description. This connects the proposed changes to the task they address and can close the Issue when the pull request is merged into the default branch.

GitHub can help future team projects by giving everyone a shared place to track tasks and review changes. My teammates and I can use Issues to define work, branches to develop separately, and pull requests to review updates before merging them. This would make it easier to coordinate an analysis and understand each person's contributions.
